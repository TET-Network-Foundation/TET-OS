## Version 1.0.0-GOLD-GENESIS (Hardware-Verified & Quantum-Ready)

This document is the operational blueprint for the TET Core May launch. It defines non-negotiable
economic invariants, security boundaries, and scalability principles.

## Non-Negotiable Invariants (Economic Constitution)
- **Hard Cap**: max supply is fixed at **10,000,000,000 TET**. Any path that exceeds the cap by even
  1 micro-stevemon must be rejected.
- **Block 0 Founder Allocation**: mint **10% (1,000,000,000 TET)** to `TET_FOUNDER_WALLET` at genesis
  (idempotent).
- **Protocol Fees (Atomic)**
  - **Mint**: **1% (bps=100)** is charged and credited to the founder wallet as part of the same
    atomic ledger transaction.
  - **Transfer**: **0.5%–1.0% (bps=50..100)** is charged and credited to the founder wallet as part
    of the same atomic ledger transaction.
- **Proof of Energy / ESR**
- **Energy Standard Ratio (ESR)**: define and expose \( \Sigma J / \Sigma TET \) as verifiable
    ledger metadata.
  - mints persist a Proof payload + SHA256 hash, designed to be upgraded to hardware attestation in
    Phase 4.

## P2P Mesh v1 (Completed)
- **Gossipsub**: `ledger` topic with lightweight announcements for Proof/Transfer/ESR.
- **Non-blocking**: the swarm loop must never be blocked (verification/DB/inference must be isolated
  via `spawn_blocking` or dedicated workers).

## Next: Practical Synchronization (State Reconciliation)
- **Delta Sync**: converge Proof/ESR from “announcements” into an eventually consistent network
  state using cursor-based paging and monotonic IDs.
- **Scale principles**
  - target 200M nodes: split retrieval by **monotonic IDs + paging**
  - shard large state later (peer-prefix / ranges / topic partitioning)

## B2B Gateway (Top Priority)
- center on an **OpenAI-compatible API** so external developers can buy TET via fiat/cards and use
  it for inference.
- the gateway is the edge boundary for **auth/billing/rate controls/auditing/abuse defense** and
  protects the P2P/swarm interior.

## Phase 4 (Launch Follow-ups)
- **Fiat Bridge (CHF/USD)**: settle/withdraw directly to CHF/USD without relying on stablecoins.
- **Hardware Attestation**: Secure Enclave / TPM 2.0 verification to prevent energy fraud.

## Security & Compliance Baseline (Final Defense)
- **Encrypted transport**: libp2p **Noise** by default; mTLS/HTTPS at the B2B edge.
- **Memory hygiene**: secret keys/seeds/critical buffers must be wiped via `zeroize` after use.
- **Invariant testing**: continuously prove hard-cap safety via property/invariant tests.
- **Audit logs**: fiat bridge / gateway / transfers require audit logs + correlation IDs.

## TET Quantum Shield (Hybrid Signature Prototype)
- **Goal**: provide a migration-safe path to post-quantum security without breaking protocol UX.
- **Hybrid requirement**: when `TET_PQC_ACTIVE=true`, state-changing requests require *dual-key*
  verification: **Ed25519 + PQC signature** (placeholder today, ML-DSA/Dilithium later).
- **Prototype note**: the current PQC verifier is a **placeholder** (not quantum-secure) and exists to
  enforce the *wire shape* and operational requirement of dual signatures from day one.

## PQC Roadmap (Deferred in v1.0)
- **Hybrid approach**: use classical crypto (Noise/Ed25519) + PQC (Dilithium/Kyber) in parallel
  (AND verification), then gradually increase PQC weight.
- **Phased rollout**
  1) add PQC signatures (optional → required)
  2) add PQC KEM for key exchange (outside Noise or via protocol extension)
  3) migrate secret key generation to TRNG (Secure Enclave/TPM)
  4) deprecate classical crypto with a defined audit/migration window

## Seamless Access & Interoperability
- **Web wallet (PWA)**: no-install UI for transfers/balances/API keys (Phase 4).
- **External chain bridges**: design ERC-20/SPL wrapping interfaces ahead of implementation.
- **HTTPS-only developer access**: developers must integrate via HTTPS requests only.
