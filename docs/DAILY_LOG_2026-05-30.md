### 1. Chain state divergence の root cause 確定

3 回の Cursor forensic 調査の末:

- parent_block_id, state_root, producer_id を含まない
- 空 coinbase block では block_id が height だけの関数
- 同 height で異なる state を持つ chain が IDENTICAL block_id を生成
- parent linkage check 通る
- divergence は tip の state_root check で初めて発覚
- catch-up tip path に reorg recovery なし → 永久 reject loop

前 2 回の Cursor 仮説 (JSON 再注入、dev_faucet) は両方とも fact ベースで否定。Cursor 自身が retract。

### 2. Block_id V2 schema 実装 (chain consensus hard fork)

- TET_BLOCK_ID_V2| prefix (V1 非衝突保証)

## Lessons (教訓)

- Block identity に state を含めない設計は危険。Bitcoin/Ethereum が parent + state を block hash に含めるのは、divergence の即座検出 + chain choice の根拠。TET の旧 schema は空ブロックで height だけになるエッジケースを見逃していた。
- Cursor を間違いから学ばせる prompt design が重要。3 回目の調査で前 2 回の誤りを明示し、fact ベースを強制した結果、Cursor 自身が前仮説を retract できた。AI 調査の信頼性は prompt 設計次第。
- Phase 0 testnet は chain core 変更のための window。Phase 1 mainnet 後では block_id schema 変更は実行不可能 (full chain reset 必要)。Phase 0 中の hard fork は cost ゼロ、benefit 巨大。
