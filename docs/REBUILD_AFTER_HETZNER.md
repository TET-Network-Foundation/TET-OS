# Rebuild after Hetzner (draft)

**Status: draft plan, nothing built.** Hetzner terminated the account. The demo (167.233.239.82), Nuremberg (46.224.223.54) and Helsinki (95.217.158.153) are gone with their disks. Nothing in this plan runs until the owner decides.

## Target

- **One host**, on a provider other than Hetzner, as both the demo and the seed (the only producer).
- **A fresh genesis.** The chain id is not `tet-local-dev`, for example `tet-testnet-2`. The founder and treasury are fresh and generated by the owner. So the genesis hash is one that no dev node shares: today every fresh dev node computes `0x9d6c…bb36`, the same hash as the old public chain.
- **The old chain is not restored.** No copy of it exists: not on the hosts, and not on the owner's Mac (checked 2026-11-10).

## Changes in the repo (agent work, each its own PR)

1. **`deploy/provision-seed.sh`**
   - No genesis defaults for a seed or demo role: `TET_CHAIN_ID`, `TET_GENESIS_FOUNDER_WALLET_ID` and `TET_TREASURY_ADDRESS` must be given.
   - It refuses `tet-local-dev` and the dev founder and treasury for those roles.
   - Add a combined `demo-producer` role. Today the demo role refuses `TET_AUTO_MINE=1`, and a follower needs a producer to follow.
   - A test in `deploy/tests/`, with a negative control (the dev chain id is refused).
2. **Bootnodes and host lists**
   - Remove the Hetzner multiaddrs from `README.md`, `docker-compose.yml`, `docs/RUNNING_A_NODE.md`, `docs/RUN_YOUR_OWN_NODE.md`, `docs/LIBP2P_CONFIG.md`, `deploy/demo/README.md`, `deploy/tests/demo-node.test.sh` and `.github/workflows/seed-liveness.yml`.
   - Add the new host once it exists. Until then, the docs say there is no public seed.
3. **UI build values:** the demo's `NEXT_PUBLIC_TET_CHAIN_ID` comes from the new chain. `verify-genesis-hash.mjs` keeps the dev golden value for dev builds only.
4. **Wording** (below): the `/try` live status (`app/try/LivePanel.tsx`), README "Limits" and the offline verifier, in en/ja/zh-HK.
5. **Offline verifier** (`build_offline_verifier.mjs`, `KNOWN.chains`): add the new chain, and keep the old one under its own name.
