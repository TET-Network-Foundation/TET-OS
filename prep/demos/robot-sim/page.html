What this showsこれが示すこと

  • Which key signed which record, in the order of the log it is given.どの鍵がどの記録に署名したか。順序は、渡されたログの順序として。
  • That no record was taken out of the middle of that log, and that a changed record is refused by its number.ログの途中から記録が抜かれていないこと。書き換えた記録は、番号を名指しして拒否されること。
  • That a one-time permit was not used twice in this log.一回限りの許可が、このログの中で二度使われていないこと。
  • Checked offline, in a folder with no key. Every record carries two signatures, Ed25519 and ML-DSA-44; replace either one alone and the record is refused.鍵のないフォルダで、オフラインで確認します。各記録には Ed25519 と ML-DSA-44 の二つの署名があり、どちらか一方だけを差し替えても拒否されます。
  • The permit sits in the same signed log as the action that uses it, and the check lists what it does not show.許可は、それを使う動作と同じ署名つきログの中にあります。確認は、示さないことも書き出します。

    What this does not show, as it stands todayこれが示さないこと(現時点)

    • It is a simulation: nothing flew or drove, and no real sensor was used.シミュレーションです。何も飛んでおらず走ってもおらず、実際のセンサーも使っていません。
    • Which machine signed: the check judges which key signed each record; it does not judge which machine held that key.どの機械が署名したか：確認するのは各記録にどの鍵が署名したかで、その鍵をどの機械が持っていたかは判断しません。
    • When each record was written: the check judges the order of records in the log it is given; it does not judge when each record was written. That the log is complete at its end: not judged.各記録がいつ書かれたか：確認するのは記録の順番で、いつ書かれたかは判断しません。ログが最後までそろっていること：判断しません。
    • Use of a permit in another log: the permit check judges reuse of a permit within one log; it does not judge use of that permit in another log. Today the vehicle signs its own permits.別のログでの許可の使用：許可の確認は一つのログの中での再使用を判断し、別のログでの使用は判断しません。今は、機械が自分で自分の許可に署名しています。
    • No public node runs today, and nobody uses this yet.現在、公開ノードは動いておらず、まだ誰も使っていません。

      Methods方法

      1. Each simulated vehicle has its own machine notebook (tools/machine-notebook) and a new test key made for this run. The simulators use fixed seeds; the status bar names them.
      2. Every step of the simulation becomes one record, signed by tet-cli with both halves (Ed25519 and ML-DSA-44) and linked to the record before it.
      3. The checker copies the log into a second folder that holds no key and runs notebook.py verify against a pin of the key kept outside both folders.
      4. The buttons change only the checker's copy; the next check says what it finds. Every signature and every signature check goes through notebook.py and tet-cli; the page's "≠ live" mark is a comparison the page makes itself.
      5. The page runs on 127.0.0.1 only and loads nothing from anywhere else.
      1. シミュレーション上の各機体は、それぞれ専用のマシンノートブック(tools/machine-notebook)と、この実行のために作った新しいテスト鍵を持ちます。シミュレーターは固定のシードを使います。シードは上の状態表示にあります。
      2. シミュレーションの1ステップが1つの記録になり、tet-cli が二つの署名(Ed25519 と ML-DSA-44)を付け、前の記録とつなぎます。
      3. 確認側は、鍵のない別のフォルダにログをコピーし、両方のフォルダの外に置いた鍵のピンに対して notebook.py verify を実行します。
      4. ボタンが変えるのは確認側のコピーだけです。次の確認が、見つけたことを報告します。署名と確認はすべて notebook.py と tet-cli を通ります。
      5. このページは 127.0.0.1 だけで動き、外部から何も読み込みません。
